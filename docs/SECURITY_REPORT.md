# Security report — October 1, 2026

## Scope and threat model

Assets are local academic records, profile/context, preferences/themes, source documents during import, exported backups, wallpaper, cached application code, and application availability. Trust boundaries are file selection → decoding, worker output → candidates, reviewed candidates → normalized aggregate, imported JSON → backup conversion, storage → UI, and static host/lockfile → browser code. A malicious document or backup can be shared with a student. A compromised dependency or deployment can ship hostile code. A person or extension with access to the browser profile can read or manipulate IndexedDB.

V1 has no account, remote student database, API, SQL queries, email/password handling, or cloud sync. The static origin is public; the academic database is local. Browser-delivered JavaScript/WASM and algorithms are inspectable. Minification and disabled production source maps reduce accidental disclosure of debugging material, not reverse engineering. No anti-debugging, fake client-secret encryption, or hostile browser behavior was added.

## Findings and mitigations

| Surface / risk | Finding and implemented control | Residual risk |
| --- | --- | --- |
| Malicious/malformed PDFs and active content | File signatures checked before PDF.js; 25 MB and 20-page caps; worker decoding; XFA disabled; embedded image limit; text/page budgets; no scripting manager, annotations, attachments, or JavaScript execution pipeline | Decoder/library/browser vulnerabilities and expensive compressed streams remain possible; a timeout is not a complete sandbox |
| Malicious images and decompression bombs | PNG/JPEG/WebP dimensions inspected before bitmap allocation; 40 MP limit; MIME/extension/signature consistency; bounded canvas dimensions; image/header corruption rejected safely | Codecs still parse untrusted bytes; wallpaper GIF/video frame complexity is handled by the browser rather than a full container validator |
| CPU/memory exhaustion | OCR worker, 180-second extraction timeout/cancellation, bounded pages/text/geometry/previews, released workers/bitmaps/canvases; timetable line assembly avoids repeated full sorting and joining | Some PDF rendering, OCR preprocessing, JSON parsing, and validation run on the main thread; large permitted files can still be slow on weak devices |
| Hostile backups / prototype pollution | 100 MB byte limit, pre-parse lexical depth/container limits, plain-data traversal, forbidden prototype-related keys, accessor/cycle rejection, strict format/version schema, explicit legacy conversion, bounds/IDs/enums/dates/times and referential validation | Exported files are not encrypted; an authorized browser-profile attacker is outside application-only isolation |
| Recovery / corrupt persisted state | Recovery records are validated before any replacement; current workspace snapshotted before restore/replacement/reset; loaded settings/records/timers/wallpaper metadata validated; corrupt state retained and recovery UI offered | A corrupt snapshot may be un-restorable; browser clearing/eviction/device failure can remove both live data and recovery copies |
| XSS, DOM/HTML/script/URL injection | Application-wide source review found no unsafe DOM insertion or eval APIs. Course names, rooms, notes, OCR/backup strings render as React text; IDs constrained; theme colours are hex-only; links are fixed, validated contact mailto, or locally created blob previews | Future rich text, arbitrary links, external embeds, or new DOM sinks would need a new review |
| Wallpaper spoofing | Allowlisted media signatures and image headers checked before storing/restoring; SVG/HTML rejected; base64 size checked before allocation; decoding in bounded chunks | Media codec behavior and possible browser decoder flaws remain outside the app's guarantees |
| Supply chain / third-party assets | Lockfile retained; all current production dependencies have identified uses; PDF/OCR/fonts are same-origin assets; generated tool manifest supplies sizes/hashes; optional offline preparation verifies them; CI actions pinned to observed commit SHAs; Dependabot configured | A compromised lockfile/build/host could change both assets and manifest; hashes are integrity checks, not protection from total host compromise |
| Exposed secrets | Source/config/env/build/public text scan; only configured project contact is a browser `VITE_` field; no backend credentials required; production source maps disabled | Pattern scans have false negatives and are not a historical Git-secret audit; this workspace has no Git history to inspect |
| Static-server traversal and response confusion | Local server accepts GET/HEAD, bounds resolved paths to `dist/`, binds loopback, serves worker/WASM MIME types, and applies security headers | Public hosting/CDN must enforce its own routing, cache, HTTPS, quotas, and DDoS mitigation |
| Service worker / stale releases / cache poisoning | Root scope declared; versioned Workbox precache; same-origin extraction cache with release hash; old extraction caches removed on activation; hourly/visibility update checks; visible update prompt; no arbitrary cross-origin runtime cache | Offline or deliberately unrefreshed clients can retain old code; actual CDN rollout and update adoption require operational verification |
| Unsafe future APIs / SQL injection / cost abuse | No backend introduced. Future requirements documented: server validation/authorization, parameterized queries, least privilege, request/file/time/concurrency limits, quotas, rate limits, and feature-specific off-device consent | Future services need their own threat model and security review |

## Browser policy

`scripts/security-headers.mjs` defines CSP, nosniff, no-referrer, Permissions-Policy, and frame denial. Worker scripts and WASM stay same-origin. `wasm-unsafe-eval` is the narrow compilation allowance for local OCR; JavaScript `unsafe-eval` and inline scripts are not allowed. Inline CSS is necessary for dynamic React/Motion styles, live theme tokens, and Radix scroll-lock styles. That exception is documented rather than represented as a strict nonce-based style policy. Untrusted input is never inserted as CSS.

The local production server applies these headers. Postbuild writes static-host equivalents and a public-route fallback. HSTS is an HTTPS-host configuration, not a localhost security feature. See [deployment requirements](DEPLOYMENT.md).

## Privacy implications

No accounts, backend, tracking, telemetry, analytics, cloud document processing, or remote student collection were added. Local recovery points are visible/deletable, and complete workspace deletion clears academic and appearance information including recovery copies. Policy text distinguishes app processing from possible host request logs. Contact information is configurable public project information. Legal documents are product disclosures and a Terms draft, not an attorney-reviewed compliance claim.

## Dependency status and repeatable checks

Run `npm run security:audit` for separate production/moderate and full/high advisory gates. The October 1 local audits reported zero known vulnerabilities for both scopes. ESLint 10 and TypeScript-ESLint were added as development tooling; production library majors were not blindly upgraded. Run `npm run security:scan` for redacted pattern findings in source, config, env, assets, and build output. The scan excludes personal development source folders and unrelated system files. No matching secrets or unsafe application DOM/code APIs were found by this scan.

Tests exercise real validation/repository behavior: script/HTML/URL-looking strings, Unicode, prototype keys, executable getters, malformed/deep/oversized JSON, unsupported versions, wrong schemas, malformed media, image bombs, invalid sessions/OCR geometry, corrupt recovery records, preservation after migration failure, and atomic state retention after rejection. Original tests remain in place. Browser injection checks and full production evidence are recorded separately in [VALIDATION.md](../VALIDATION.md).

## Not verified and release risks

This is a development security review, not a penetration-test certification. No guarantee of being unhackable or completely secure is made. The later public main baseline passed hosted GitHub CI and 34 live HTTPS route/asset/header checks; the new local onboarding fix needs its own CI/deployment verification after push. Physical devices, every media codec/browser, fuzzing of all PDF streams, browser extension behavior, power consumption and public-host incident/update operations require broader verification. Private vulnerability reporting is currently disabled. Operator identity, monitored contact, a private reporting channel, source license and qualified legal review remain release decisions. The concrete checklist is in [RELEASE_READINESS.md](RELEASE_READINESS.md).
